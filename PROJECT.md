# 1. КОНТЕКСТ

Aura Robotics — поставщик робототехники и роботизированного оборудования из Китая в Россию. Компания закупает напрямую на китайских заводах по внешнеторговому контракту. Своего склада и шоурума нет — осознанная модель, дающая клиенту экономию 15–30% относительно поставщиков с наценкой российского импортёра.

**Юридическое лицо китайское.** Все поставки под конкретный заказ. Формулировок про официальное дилерство на сайте быть не должно нигде.

**Четыре направления:**
1. **Роботы** — каталог по заводам-производителям
2. **Оборудование для производств** — пищепром и смежные отрасли
3. **Aura Robotics Tour** — закупочные поездки клиентов по китайским заводам
4. **Консалтинг** — наполняется позже

**Главное доказательство компетентности** — фото и видео с заводов, включая тестовый прогон конкретного экземпляра перед отгрузкой с серийным номером в кадре. Съёмка ведётся на телефон и подаётся как документальное свидетельство. Подпись к каждому кадру обязательна.

**Аудитория:** директора производств, технологи пищевых предприятий, руководители складов, владельцы сетей HoReCa и ретейла, закупщики вузов и клиник. Средний чек 0,5–6 млн ₽, цикл сделки 1–6 месяцев.

**Цель сайта:** заявка с указанием конкретного завода или регистрация на тур.

# 2. СТЕК

```
Next.js 15, App Router, TypeScript strict
Tailwind CSS v4
Motion (framer-motion)
Языки: русский и английский, next-intl
Каталог, туры, консалтинг: Google Sheets → CSV → JSON при сборке

Деплой: Vercel, ISR с ревалидацией раз в час
```

Правила:
- Никаких `any`. Все сущности через zod, данные валидируются при сборке. Битая строка не роняет сборку — логируется и пропускается.
- Серверные компоненты по умолчанию, `"use client"` только для интерактива.
- Изображения через `next/image`. Видео — эмбедом, не файлом.
- Ни одного заглушечного текста. Нет данных — блок не рендерится.

# 5. КЛЮЧЕВЫЕ ЭКРАНЫ

### 5.1 Каталог роботов

`/catalog/[category]`:
- Хлебные крошки, H1, SEO-описание категории сверху
- Строка метрик: диапазон цен, срок поставки, число заводов
- Фильтры: отрасль, бюджет, назначение, срок. Состояние в URL query params
- Заводы с `featured: true` — крупными карточками сверху, остальные компактной сеткой
- Сравнение до 3 заводов таблицей
- Блок «Как выбрать», FAQ категории, форма

Клик по заводу открывает **модальное окно** (URL меняется shallow — работают «назад» и прямая ссылка):
- Название, китайское название, страна, город, год основания
- Описание, теги отраслей — кликабельны, ведут на страницу отрасли
- Метрики: диапазон цен категории, срок поставки
- Фото и видео тестового прогона
- Форма заявки — состав в разделе 9

### 5.2 Оборудование для производств

Переиспользует компоненты каталога. Двухосевой вход: от подотрасли и от типа оборудования, обе оси ведут к пересечению.

Страница пересечения: H1 «Оборудование для фасовки молочной продукции», специфика отрасли (гигиена, температурный режим, санобработка, ХАССП), карточки поставщиков с формой, типовые конфигурации линии, кейс, FAQ, форма.

### 5.3 Aura Robotics Tour

`/tours/[id]` — блоки по порядку:
1. Шапка: название, даты крупно, города, кнопка «Забронировать место»
2. Счётчик мест и дней до закрытия — только если данные заполнены
3. Для кого — из блока `forWhom`
4. Что вы получите — из блока `youGet`
5. **Программа по дням** — таймлайн из `tour_days`
6. Заводы в программе — карточки со ссылками в каталог
7. Что входит и что не входит — две колонки
8. **Стоимость** — таблица из `tour_costs`, см. 5.4
9. Преимущества маршрута
10. Галерея и видео с прошлых поездок
11. Отзывы участников
12. FAQ — пары `faqQuestion` и `faqAnswer` с одинаковым `order`
13. Форма регистрации

**Всё вычисляется из данных:**
- «3 города» — из `cities`
- «5 дней» — из числа строк `tour_days`
- «12 компаний» — из уникальных значений `companies` во всех днях
- Обратный отсчёт — от `registrationDeadline`
- Итоговая сумма — сложением `tour_costs`

**Пустые даты** — вместо блока дат «Даты формируются, оставьте заявку».
**Статус `прошла`** — поездка уходит в архив на `/tours`.

Связка с каталогом: на карточке завода плашка «Этот завод в программе тура [даты]», если он есть в активной поездке. Если идентификатор компании не найден в каталоге — выводится текстом, без ссылки, сборка не падает.

### 5.4 Блок стоимости тура

Заголовок: **«Полная стоимость — от [сумма] ₽ на участника»**, где сумма = все `fixed` + все `estimate`.

Ниже две группы:
- **Программа — [сумма fixed] ₽, фиксированная стоимость** — таблица статей с `type: fixed`
- **[Название] — около [сумма] ₽, оплачивается отдельно** — статьи с `type: estimate`, с пояснением из `note`

Внизу: «Программа рассчитана на N дней визитов. Проживание и питание — на сутки больше: заезд накануне, вылет после завершения.»

Ни одна сумма не вписывается в код.

### 5.5 Консалтинг

`/consulting` — структура:
1. Заголовок и описание направления — из справочника в коде
2. Карточки услуг из вкладки `consulting`, сортировка по `order`
3. Для кого
4. Как мы работаем — 3–4 шага
5. Кейсы из Notion по тегу `consulting`
6. FAQ
7. Форма «Опишите задачу», метка `consulting_request`

Блоки 2–6 не рендерятся при отсутствии данных.

**Поведение при пустой таблице:** страница существует и открывается, показывает заголовок, описание направления и форму. **В главном меню не отображается.** Пункт появляется автоматически, когда есть хотя бы одна опубликованная услуга.

Пустая цена — «Стоимость по запросу».

### 5.6 Квиз — 4 шага

| Шаг | Вопрос | Формат |
|---|---|---|
| 1 | Отрасль | 7 плиток с иконками, выбор сразу ведёт дальше |
| 2 | Задача | Плитки, зависят от шага 1 |
| 3 | Сколько человек занято задачей и сколько получает | Два числовых поля на одном экране |
| 4 | Имя и телефон | Два поля |

**Экран результата показывается после шага 3, до ввода контактов:**
- Рекомендованная категория, 2–3 подходящих завода карточками
- Расчёт: текущие затраты `сотрудники × ФОТ × 12 × 1.3`, стоимость решения из вилки категории, экономия в год, срок окупаемости
- Цифры анимированно набегают от нуля
- Подпись: «Предварительная оценка. Точная — в коммерческом предложении»
- Ниже — шаг 4 с контактами

Подбор детерминированный, через таблицу соответствий `matching.ts`. Никакого ИИ.

### 5.7 Как проходит поставка

Шесть шагов: подбор и КП → договор и оплата → закупка на заводе → приёмка и тесты → логистика и таможня → монтаж и запуск. Шаги 3 и 4 самые подробные, они заменяют шоурум и поддерживают галерею.

На десктопе — закреплённая схема слева, шаги прокручиваются справа. На мобильных схема отключается, шаги становятся вертикальным списком с раскрытием.

### 5.8 Карта заводов и индекс цен

Карта: интерактивная база с фильтрами по категории, отрасли, городу, ценовому сегменту. Поиск. Открытый доступ, экспорт в PDF за почту. На мобильном по умолчанию список, карта по кнопке.

Индекс цен: средние цены по категориям, динамика по кварталам, влияние курса, сроки. Графики.

### 5.9 Партнёры и R&D

Отдельная страница для компаний, которые не продают роботов: поставщики компонентов, разработчики моделей и данных, технологические партнёры. Оформляется как экосистема, без кнопки «запросить расчёт».

### 5.10 FAQ

Десять разделов, около 65 вопросов, аккордеон, поиск по странице, якоря на каждый вопрос, разметка `FAQPage`.

# 6. ДИЗАЙН

Редакционная система, светлая, монохром плюс единственный акцент. Источник — дизайн-система robot.com.

**Значения помечены источником.** «Шаблон» — брать буквально. «Производное» — адаптация под кириллицу и мобильные, приоритетнее шаблона.

### Цвета [шаблон]

```
--color-accent:           #fff65d   единственный хроматический цвет
--color-canvas:           #ffffff
--color-warm-parchment:   #f8f6f3   поверхность карточек
--color-fog:              #d9d7d5   тихий разделитель
--color-ash:              #8f8e8d   третичный текст
--color-stone:            #727272   вторичный текст
--color-ink:              #262626   основной текст и тёмные секции
--color-charcoal:         #2d2d2d
--color-pure-black:       #000000   одна кнопка на экран, не больше
```

Жёлтый — только фоновые блоки и один акцент на экран. Никогда не текст, никогда не подложка под текст. Ритм секций: белый → парчмент → тёмный → жёлтый. Без градиентов, без теней, без засечек. Глубина — контрастом цветовых блоков.

### Типографика

**Inter**, подмножество с кириллицей, `font-display: swap`, начертания 400/500/600.
**JetBrains Mono** [производное] — подписи к фото, характеристики, цифры.

| Роль | Десктоп | Межстрочный | Трекинг | Мобильный | Трекинг моб. |
|---|---|---|---|---|---|
| display-xl | 100px | 0.96 | −0.02em | 40px | −0.01em |
| display | 72px | 1.0 | −0.02em | 34px | −0.01em |
| heading-lg | 52px | 1.06 | −0.015em | 28px | −0.005em |
| heading | 38px | 1.1 | −0.01em | 24px | 0 |
| heading-sm | 24px | 1.16 | −0.005em | 20px | 0 |
| subheading | 18px | 1.22 | −0.18px | 18px | 0 |
| body | 16px | 1.25 | 0 | 16px | 0 |
| body-sm | 14px | 1.22 | 0 | 14px | 0 |
| caption | 12px | 1.22 | 0 | 12px | 0 |

⚠️ **В исходном шаблоне указан трекинг −0.214em при 100px. Не использовать** — при кириллице буквы накладываются. Максимальный отрицательный трекинг на проекте −0.02em.

Минимальный размер текста 14px, основного 16px, полей форм не менее 16px — иначе Safari на iOS увеличивает экран при фокусе.

### Размеры и формы [шаблон]

```
Базовая единица      4px
Контейнер            1280px
Отступ секций        64px десктоп / 40px мобильный
Паддинг карточки     24px
Радиусы: 30px кнопки · 24px теги и чипы · 10px карточки · 4px фильтры и таблицы
```

**Разночтение шаблона:** в таблице радиусов карточки 24px, в описании компонента 10px. Используем **10px для всех карточек контента** единообразно.

### Навигация [отступление от шаблона]

Шаблон предполагает плавающую пилюлю. **Используем обычную панель с выпадающими списками.** Язык пилюль сохраняется для кнопок, тегов и чипов.

### Логотип

Компонент берёт SVG из `public/logo.svg`. При отсутствии файла выводит текст «AURA ROBOTICS» шрифтом Inter. Замена файла не должна требовать правки кода.

### Фотография

Полноэкранные фото без рамок и скруглений. Исключение — карточки каталога: поверхность `#f8f6f3`, радиус 10px, граница 1px `#262626`.

Съёмка ведётся на телефон и подаётся документально: подпись моноширинным шрифтом 12px, цвет `#727272` — что снято, где, когда, серийный номер если виден.

Вертикальные ролики 9:16 не вставляются в горизонтальные полноэкранные блоки.

### Анимации

Появление секции: fade + сдвиг 24px, 400 мс, ease-out, один раз. Ховер карточки: подъём 4px + подсветка обводки, 200 мс. Каскад карточек: задержка 60 мс. Счётчики отсчитывают при попадании в область видимости.

Не более двух анимированных элементов на экран. `prefers-reduced-motion` отключает всё.

**Запрещено:** параллакс во всю высоту, частицы, кастомный курсор, прелоадер, автовоспроизведение со звуком.

### Внешние библиотеки компонентов

Готовые компоненты допускается использовать только как основу разметки. Все декоративные свойства — градиенты, тени, свечения, радиусы, цвета, анимации — заменяются на значения из токенов. Компонент, сохранивший визуальные признаки исходной библиотеки, считается не готовым.

# 7. МЕДИА-СЛОТЫ — КРИТИЧЕСКОЕ ТРЕБОВАНИЕ

Сайт запускается почти без фотографий. Медиа добавляются порциями месяцами после запуска.

**Каждая секция, которая когда-либо будет содержать медиа, проектируется со слотами с первого дня. Добавление фотографии обязано быть заполнением поля в данных, а не правкой компонента. Если для вставки снимка нужно тронуть JSX — задача решена неверно.**

### Правила

1. **Медиа не хардкодятся в компонентах.** Ни одного `<Image src="/photos/factory1.jpg">` в JSX.
2. **Контейнер держит размер независимо от наличия медиа** — через `aspect-ratio`. Появление фото не сдвигает вёрстку.
3. **У каждого слота определено поведение при пустом значении:** `hidden` (блок не рендерится), `placeholder` (нейтральная заглушка без надписей), `fallback` (запасное изображение). Битых картинок и пустых дыр быть не должно.
4. **Один слот принимает и фото, и видео.** Компонент определяет тип по значению.
5. **Подпись — обязательное поле рядом с каждым медиа.** Слот без подписи считается незаполненным.
6. **Вертикальные и горизонтальные медиа в разных полях**, рендерятся разными компонентами.

### Компоненты

`<MediaSlot>` — одна единица с подписью и обработкой пустого значения.
`<MediaGallery>` — набор слотов.
`<VerticalVideoWall>` — сетка вертикальных роликов, автовоспроизведение без звука.

Ни одна секция не рендерит медиа напрямую.

### Где обязательны слоты

Карточка завода · шесть шагов поставки · карточка кейса с хроникой · страница тура · услуги консалтинга · отрасли и подотрасли · о компании · блог и R&D · главная · отдельная страница «Стена с производств».

### Именование

Поля во всех сущностях называются одинаково: `photos`, `photoCaptions`, `videoUrl`, `verticalVideos`. Никаких `image1`, `img_main`, `pic`.

### Критерий приёмки

**Собрать сайт с полностью пустыми медиа-полями. Он должен выглядеть законченным.** Затем заполнить одно поле и убедиться, что фото встало без единой правки кода.

# 8. АДАПТИВНОСТЬ — КРИТИЧЕСКОЕ ТРЕБОВАНИЕ

Мобильный трафик 40–50%. Решение о закупке принимается на десктопе, первое знакомство — почти всегда с телефона.

**Каждый экран верстается мобильным в первую очередь. Компонент не считается готовым, пока не проверен на 375px. Адаптив — часть каждого этапа, а не финальный этап.**

### Брейкпоинты

```
Мобильный          375–767px    базовый
Планшет            768–1023px
Планшет широкий    1024–1279px
Десктоп            1280px+
```

Проверять на: 375, 390, 414, 768, 1024, 1440.

### Поведение компонентов

**Навигация.** Десктоп — панель с выпадающими списками. Мобильный и планшет вертикальный — кнопка меню, полноэкранный слой, направления аккордеоном. Закрытие по выбору пункта и по свайпу. Контакты и кнопка заявки закреплены внизу слоя.

**Каталог.** Карточки: одна колонка мобильный, две планшет, три десктоп. Фильтры — кнопка, открывающая шторку снизу; выбранные фильтры чипами с горизонтальной прокруткой; счётчик найденных виден всегда.

**Модалка карточки завода.** Десктоп — окно поверх страницы. Мобильный — полноэкранный лист снизу с закреплённой шапкой, закрытие свайпом. Выпадающие списки — нативные элементы управления.

**Формы.** Одна колонка. `type="tel"` и `type="email"`. Кнопка на всю ширину. Область нажатия чекбокса не менее 44px.

**Квиз.** Один вопрос на экран, крупные области нажатия. Прогресс сверху, навигация внизу. Экран результата вертикальный, цифры не мельче 20px.

**Поставка.** Закреплённая схема отключается, вместо неё вертикальная последовательность с раскрытием.

**Таблицы.** Сравнение заводов — карточки с построчным сопоставлением либо горизонтальная прокрутка с закреплённой первой колонкой. Смета тура — вертикальный список, не таблица.

**Карта заводов.** По умолчанию список, карта по кнопке.

**Медиа.** Фоновые видео на мобильных отключаются полностью, только постер. Стена вертикальных роликов — одна колонка.

**Анимации.** На мобильных отключаются: закреплённые схемы, параллакс, каскадные появления.

**Страница тура.** Программа по дням — вертикальный список. «Что входит / что не входит» — две секции друг под другом. Кнопка регистрации закреплена внизу при прокрутке.

### Технические требования

- Область нажатия не менее 44×44px, между соседними не менее 8px
- Горизонтальной прокрутки страницы не существует ни на одном разрешении
- `next/image` с корректными `sizes`
- Смена ориентации не теряет состояние: фильтры, шаг квиза, позиция прокрутки

### Критерий приёмки

**Пройти на 375px весь путь: главная → каталог → категория → фильтры → карточка завода → отправка заявки. Затем весь квиз. Затем страницу тура до регистрации.** Ни одного горизонтального скролла, ни одного нечитаемого текста.

Lighthouse mobile: производительность ≥ 80, доступность ≥ 95.

### Телефон

Тип `tel`. Форматирование по мере ввода. Принимать ввод в любом виде — с восьмёркой, с плюсом, с пробелами — и приводить к единому формату молча.

### Согласие

Чекбокс не отмечен по умолчанию. Текст с работающей ссылкой: «Нажимая кнопку, я соглашаюсь с политикой обработки персональных данных». Область нажатия — весь текст.

### Запрещено

Всплывающие окна с формой при входе. Окна раньше 30 секунд на странице. Каптча — вместо неё скрытое поле-ловушка и ограничение частоты по адресу. Поля «Бюджет», «Сроки», «Должность». Обязательная компания везде, кроме тура. Требование телефона и почты одновременно, кроме тура.

Открытие: затемнение, появление с лёгким увеличением, 200 мс. Закрытие: крестик, Escape, клик по затемнению. Фон не прокручивается. Фокус переходит внутрь и не выходит при Tab. После закрытия фокус возвращается на карточку.

| Тип | Вид | Сколько на экран |
|---|---|---|
| Основная | Заливка `#000000`, текст белый | Одна |

Любое действие получает отклик в пределах 100 мс: нажатие кнопки — визуальное нажатие, фильтр — обновление счётчика, копирование контакта — «Скопировано» на 2 секунды, отправка — блокировка и индикатор, загрузка — скелетоны.

Все интерактивные элементы достижимы клавишей Tab в логическом порядке. Видимая рамка фокуса 2px `#262626` с отступом 2px, не убирать через `outline: none`. Каждое поле имеет связанную подпись. Контраст текста не ниже 4.5:1 — проверить `#8f8e8d` на белом, при недостатке использовать `#727272`. Изображения имеют `alt`. Модальные окна и меню закрываются Escape.
