# CLAUDE.md — Aura Robotics

Полная бизнес-спецификация: `PROJECT.md`. Дизайн-токены: `design/tokens.md`.
Бриф по турам: `brief/mission-august.md`. Этот файл — карта архитектуры кода
для последующих этапов сборки (PROJECT.md, раздел 14).

## Стек

Next.js 15 (App Router) · TypeScript strict · Tailwind CSS v4 · next-intl ·
zod · motion. Данные каталога/туров/консалтинга — Google Sheets → CSV → JSON
при сборке. Кейсы/блог — Notion API (подключается в этапе 9).

## Как запустить

```
npm install
npm run sync   # тянет CSV (или локальный снимок) → data/*.json
npm run dev
```

`data/*.json` — сгенерированные файлы, в git не лежат (см. `.gitignore`).
Без `npm run sync` списки каталога/туров/консалтинга будут пустыми —
секции, зависящие от данных, просто не рендерятся (см. «Философия
пустых данных» ниже), сайт не падает.

## Структура

```
src/
  app/
    [locale]/
      layout.tsx      — html/body, шрифты, Header/Footer, generateStaticParams
      page.tsx         — главная (минимальная заготовка; полная — этап 6)
    globals.css        — токены дизайна (@theme), сброс, prefers-reduced-motion
  i18n/
    routing.ts          — locales ru/en, ru без префикса (localePrefix: as-needed)
    request.ts          — конфиг next-intl; en с фолбэком на ru при отсутствии ключа
    navigation.ts        — Link/redirect/usePathname с учётом локали
  components/
    layout/             — Header (dropdown-нав), Footer, Logo (fallback на текст)
    media/               — MediaSlot, MediaGallery, VerticalVideoWall
  lib/
    schemas.ts           — zod-схемы всех 7 сущностей + CSV-row трансформеры
    csv.ts                — минимальный RFC4180-парсер CSV
    data.ts                — типизированные геттеры data/*.json (пусто, если файла нет)
    reference-data.ts       — industries/subIndustries/equipmentTypes/services/executions
scripts/
  sync-data.ts           — CSV → zod → JSON (см. ниже)
data/source/*.csv         — снимок реальных вкладок таблицы (пока нет publish-ссылок)
messages/{ru,en}.json     — тексты интерфейса (не данные каталога/туров)
```

## Поток данных

`scripts/sync-data.ts` для каждой из 7 вкладок:

1. Берёт CSV из переменной окружения `GOOGLE_SHEETS_CSV_<TAB>` (публикация
   Google Sheets), а если её нет — из `data/source/<tab>.csv` (локальный
   снимок, тот же формат). Подключение реальной таблицы — это добавление
   переменных окружения, без правки кода.
2. Парсит через `parseCsv` (`src/lib/csv.ts`).
3. Валидирует каждую строку `*RowSchema` из `src/lib/schemas.ts` (zod).
   Битая строка логируется в консоль и пропускается — сборка не падает
   (PROJECT.md, раздел 3).
4. Пишет валидные строки в `data/<tab>.json`.

`src/lib/data.ts` читает эти JSON-файлы на сервере (`getFactories()`,
`getCategories()`, ...). Файла нет или пуст — геттер возвращает `[]`.

## Философия пустых данных

MediaSlot/MediaGallery/VerticalVideoWall и любые списочные секции не
рендерятся (`hidden`), показывают нейтральную заглушку (`placeholder`)
или запасное изображение (`fallback`) при отсутствии данных — решает
вызывающий компонент через проп `emptyBehavior`. **Слот без подписи
считается незаполненным**, даже если файл есть (PROJECT.md, раздел 7) —
это уже implemented в `MediaSlot`.

Тот же принцип на уровне данных: пустая/битая строка не ломает сборку,
просто не попадает в JSON. Значит каталог, тур и консалтинг могут
существовать в коде задолго до того, как в таблице появятся все поля.

## Дизайн-токены

`src/app/globals.css` — `@theme` с цветами, радиусами, шрифтами и
типографической шкалой из `design/tokens.md`. Мобильные размеры шкалы —
значения по умолчанию (mobile-first), десктопные подключаются через
`@media (min-width: 1280px)` (брейкпоинт «десктоп»). Трекинг ограничен
−0.02em максимум (шаблонное −0.214em при 100px даёт слипание кириллицы —
не используется, см. design/tokens.md).

Кастомные Tailwind-брейкпоинты: `tablet` (768px), `tablet-lg` (1024px),
`desktop` (1280px) — заданы как `--breakpoint-*` в `@theme`.

## i18n

`ru` — язык по умолчанию, без префикса в URL; `en` — с префиксом `/en`
(`localePrefix: "as-needed"`). Отсутствующий ключ в `messages/en.json`
не оставляет пустое место — `src/i18n/request.ts` собирает en поверх
ru через глубокое слияние. Для полей данных (`title_en`, `description_en`
и т.п.) тот же принцип нужно будет соблюдать в компонентах следующих
этапов: если `_en` пусто — показывать `_ru`, а не пустую строку.

## Навигация

Обычная панель с выпадающими списками (не плавающая пилюля — см.
design/tokens.md, «Навигация»). Пункт «Роботы»/«Оборудование для
производств» становится обычной ссылкой без выпадашки, если для этого
сегмента нет ни одной валидной категории (сейчас так и есть, пока не
заполнены цены) — не показываем пустое меню. «Консалтинг» полностью
скрыт из меню, пока нет опубликованных услуг.

## Решения, принятые по умолчанию (стоит перепроверить с заказчиком)

- Маршрут тура — `/tours` (как в PROJECT.md, который явлен единственным
  источником истины), а не `/missions` (как упомянуто в брифе — там это,
  похоже, было рабочее название раздела, а не факт архитектуры).
- Скаффолд — стандартный Next.js 15 App Router, `src/` директория,
  alias `@/*`, ESLint flat config через `next/core-web-vitals` +
  `next/typescript`.
- Zod v4 (а не v3) — новее, PROJECT.md версию не фиксирует.
- Vercel/домен не подключены — по спецификации это этап 12.

## Этап 2 — каталог роботов

`/catalog` (хаб категорий) и `/catalog/[category]` (хлебные крошки,
метрики, фильтры в URL, сетка карточек, сравнение до 3 заводов,
модалка карточки завода). Ключевые решения:

- **Отрасль как фильтр** — колонка `industries` в factories.csv гораздо
  детальнее семи отраслей сайта (`metalwork`, `oilgas`, `pharma`, ...).
  Подписи для фильтра берутся из отдельного словаря
  `src/lib/industry-tags.ts`, а не из `reference-data.ts`, иначе
  большинство тегов потеряло бы фильтруемость.
- **«Бюджет» и «назначение» как отдельные фильтры не реализованы** —
  цена задана на уровне категории, а не завода/модели, и поля
  «назначение» в схеме нет. Останется актуальным, если модель данных
  расширится в следующих этапах.
- **Теги отраслей на карточке завода не кликабельны** — они не входят в
  список семи отраслей сайта, под которые рассчитаны страницы
  `/industries/[industry]` (этап 5); ссылка на гарантированно
  несуществующий фильтр хуже, чем плашка без ссылки.
- **Модалка карточки завода** — параллельный + перехватывающий роут
  (`@modal/(.)factory/[factoryId]`) поверх обычного `factory/[factoryId]`:
  URL меняется, «назад» и прямая ссылка работают, как того требует
  PROJECT.md 5.1.
- **`LeadForm` и `/api/lead`** — общий компонент формы и единый
  обработчик уже работают (валидация, состояния отправки, блок
  подтверждения), но `/api/lead` пока только логирует заявку. Реальная
  отправка на почту, вебхук CRM, Telegram-бот, UTM-cookie и
  rate-limiting — этап 10, без изменения контракта обработчика.
- **Блок «Как выбрать»** — статический общий текст для всех категорий
  робот-сегмента, не из данных (в схеме нет поля под него).

Каталог визуально проверен вручную: временно добавлялась одна
QA-категория с ценами (`data/categories.json`, не коммитится) — экран
хаба, страницы категории, фильтров, модалки, сравнения и отправки
формы прошли на 1440px и 375px. Тестовые данные откачены обратно
(`npm run sync`) перед коммитом; в бою `data/categories.json` пуст,
пока в таблице не заполнены цены категорий.

## Этап 3 — оборудование для производств

Двухосевой вход: `/production/[industry]` (11 подотраслей, `src/lib/
reference-data.ts`) и `/production/equipment/[equipment]` (10 типов
оборудования, тот же файл) — обе оси **всегда существуют**, это код,
а не данные из таблицы. `/production/[industry]/[equipment]` —
пересечение, генерируется только там, где реальный завод покрывает обе
оси одновременно (`getIntersectionParams`, PROJECT.md раздел 4). Прямо
сейчас это ровно одна пара: мясопереработка × мойка и санобработка
(завод YANC) — проверено на реальных данных, без QA-заглушек.

- **Сопоставление осей с данными завода** — подотрасль ищется по
  точному совпадению тега в `factory.industries` с id из
  `subIndustries`; тип оборудования — по вхождению id в
  `factory.categories` (у него тот же id, что и у категории в
  `categories.csv`, если она заведена). Тегов и категорий, не
  совпадающих с этими справочниками, в данных сейчас больше, чем
  совпадающих — это ожидаемо, ровно то же расхождение, что на стороне
  каталога роботов (`industry-tags.ts`), просто здесь ось задана кодом,
  а не собирается из данных.
- **Карточка поставщика без модалки и сравнения** — `SupplierCard`, не
  `FactoryCard`: раздел 5.2 описывает только карточки с формой, ни
  модалки, ни сравнения для этого раздела в спецификации нет.
- **H1 пересечения** — «[оборудование] — [подотрасль]» через тире, а
  не грамматическое согласование («оборудование для фасовки молочной
  продукции» из примера в спеке потребовало бы склонения названия
  подотрасли в родительный падеж, что нельзя надёжно сделать
  программно для производных из таблицы названий).
- **Гигиена/ХАССП, типовые конфигурации линии, кейс, FAQ** — из раздела
  5.2 сделан только гигиенический блок (общий статический текст, не по
  данным — поля под него в схеме нет). Типовые конфигурации и кейс
  зависят от Notion (этап 9), FAQ пересечения — от модели данных,
  которой пока нет; оба оставлены на потом явно, не тихо пропущены.

## Этап 4 — квиз

`/quiz`, 4 шага (`src/components/quiz/quiz-flow.tsx`), экран результата
показывается после шага 3, до контактов (PROJECT.md 5.6).

- **Таблица соответствий** (`src/lib/quiz-matching.ts`) — полностью
  детерминированная, без ИИ. Отрасли — это ровно `industries` из
  `reference-data.ts` (семь штук, 1:1 с сайтовым справочником, в
  отличие от расхождений на страницах каталога и оборудования).
  Задача каждой отрасли и категория, в которую она матчится, — мой
  выбор на основе реальных 25 категорий `categories.csv`; в спеке
  конкретные пары «задача → категория» не заданы, только формат шага.
- **Расчёт** (`src/lib/quiz-calc.ts`) — текущие затраты
  `сотрудники × ФОТ × 12 × 1.3` по формуле спеки буквально. Стоимость
  решения — середина вилки цены категории (мин/макс в спеке не
  уточняется, какую брать). Экономия в год = текущие затраты (модель
  «робот замещает труд полностью», без учёта эксплуатационных
  расходов робота — упрощение, раз в спеке нет более точной формулы).
  Срок окупаемости = стоимость решения / (экономия за год / 12).
- **Если категория ещё не оценена** (нет валидной строки в
  `categories.csv` — сейчас так для всех) — экран результата не ломает
  расчёт, а показывает «решение уточняется» и форму контактов, без
  циферных блоков. Проверено на реальных данных: сейчас в этом
  состоянии оказываются все пары квиза, в отличие от этапа 3, где для
  производства нашлась одна живая пара — здесь пересечение «задача из
  квиза → приоритетная категория с ценой» ещё не наступило ни разу.
- **Иконки отраслей** — свои inline SVG (`industry-icon.tsx`), не из
  библиотеки, чтобы не тащить чужой визуальный стиль (design/tokens.md,
  «Внешние библиотеки компонентов»).
- **Счётчики** — `CountUp` учитывает `prefers-reduced-motion` и
  показывает финальное значение сразу, если анимации отключены.

## Этап 5 — контентные страницы

`/delivery`, `/industries/[7]`, `/services/[4]`, `/about`, `/partners`,
`/faq`, `/contacts`, `/payment`, `/policy` + колонка ссылок в футере.
Редакционный контент живёт в `src/lib/content/*.ts` (ru/en поля, тот же
паттерн, что reference-data) — это данные, а не JSX: фото к шагам
поставки добавляются заполнением `photos/photoCaptions` в
`content/delivery.ts`.

- **FAQ** — стартовый набор ~20 вопросов в 6 разделах, честно выведенных
  из PROJECT.md и брифа. Спека закладывает ~65 вопросов в 10 разделах —
  добор это контент от владельца (строки в `faq-content.ts`), не код.
  Поиск по странице, якоря, аккордеон уже работают на любом объёме.
- **`/agreement` и `/offer` не созданы** — юридические тексты (договор
  оферты, пользовательское соглашение) должен дать владелец; выдумывать
  их опаснее, чем не иметь страниц. `/policy` написана (стандартная
  политика ПД, на неё ссылается чекбокс согласия форм). `/warranty`
  тоже отложена — условий гарантии как контента не существует, FAQ

- **Партнёры** — отбор из данных: categories содержит components/
  controllers или research-профиль без категории humanoid, и завод не
  featured (featured = активные продавцы, им не место на странице «без
  кнопки расчёта»). Сейчас это Seer Robotics и LinkerBot.
- **Отрасли** — 7 страниц всегда существуют (справочник в коде), заводы
  подтягиваются через `factoryTags` в `industries-content.ts`.
- **Метки форм** — для отраслей/услуг в спеке меток нет; использованы
  `industry_request` и `service_request` по образцу существующих.
- **Карта в контактах** — не встраивалась (внешний эмбед-провайдер не
  выбран); адрес офиса в Путо указан текстом. Решить на этапе 12.

## Этап 6 — главная

Ритм секций по токенам: белый (хиро) → парчмент (направления) → тёмный
(цитата + счётчики) → белый («Почему с нами дешевле») → парчмент
(рекомендуемые заводы) → жёлтый (промо квиза) → белый (тизер тура) →
форма.

- **Цифра рынка** — в тёмной полосе использована защищаемая формулировка
  из брифа («Более половины всех промышленных роботов в мире
  устанавливается в Китае»), а не запрещённые брифом «86% рынка».
- **Счётчики** — только из данных: число опубликованных заводов и
  уникальных городов. `CountUp` теперь стартует при попадании в
  видимость (IntersectionObserver), `format` опционален — серверные
  компоненты не могут передавать функции клиентским.
- **Карточка консалтинга** в «направлениях» появляется только при
  опубликованных услугах — то же правило, что для пункта меню.
- **Тизер тура** — из tours.json; пустые даты дают «даты формируются,
  оставьте заявку» (5.3). Ссылки на /tours начнут работать после
  этапа 7 (хедер ссылается на /tours с этапа 1 — поведение одинаковое).
- **Метка формы** — `home_request` (в таблице форм спеки главной нет),
  по образцу остальных.

## Этап 7 — туры

`/tours` (активные + архив по статусу «прошла») и `/tours/[id]` — все
13 блоков раздела 5.3 по порядку, каждый рендерится только при наличии
данных. Слой данных — `src/lib/tours.ts`.

- **Все счётчики из данных**: города из `cities`, дни из числа строк
  tour_days, компании из уникальных `companies`, суммы сметы сложением
  tour_costs (5.4: «Полная стоимость — от [fixed+estimate] ₽»),
  обратный отсчёт от registrationDeadline (сейчас пуст — скрыт).
- **FAQ тура** — пары по одинаковому `order`; ответы, начинающиеся с
  «ЗАПОЛНИТЬ»/«TO FILL» в таблице, считаются незаполненными и не
  рендерятся (правило «ни одного заглушечного текста»). Сейчас видимых
  пар две; остальные появятся сами после заполнения таблицы.
- **Заводы программы** — три состояния: ссылка в каталог (завод есть и
  его категория заведена с ценой), карточка без ссылки (завод есть,
  категории с ценой нет — сейчас так у всех, пока categories пустые),
  текст (id не найден). Сборка не падает ни в одном случае.
- **Плашка в каталоге** — «Этот завод в программе тура [даты]» на
  карточках и в деталке завода; берётся из активной поездки
  (статус «набор»/«анонс»); без дат — вариант без дат.
- **Кнопка регистрации** закреплена внизу экрана на мобильных;

## Обязательность полей в схемах (важно)

Каталог однажды оказался пустым при 25 строках в таблице: схема
категории требовала priceMin/priceMax/leadTime/description_ru, а
владелец заполнил только id, названия и сегмент — все строки
отбраковывались валидацией и `categories.json` оставался `[]`.
То же с четырьмя заводами без города.

Правило: **обязательными в схемах делаем только те поля, без которых
запись не имеет смысла** (идентификатор, название, сегмент, связь).
Всё, что владелец заполняет постепенно — цены, сроки, описания,
город, медиа — `optional`, а интерфейс показывает «Цена по запросу» /
скрывает блок. Это и есть «пустые данные не ломают сайт» из
PROJECT.md: строка должна попадать на сайт неполной, а не исчезать.
При отладке пустых разделов первым делом смотреть вывод `npm run sync`
— он печатает каждую отброшенную строку с причиной.

  страницу категории (в отличие от `/catalog`, где живут все категории
  с первого дня).
- В `categorySchema` добавлено опциональное поле `photo` (колонка в
  `categories.csv`) — по тому же принципу, что и everywhere: пока
  пусто, карточка показывает заглушку в стиле `.media-slot-empty`
  (та же сетка, что и у пустых MediaSlot по всему сайту) с подписью
  «Фото — в подготовке» и названием категории; как только владелец
  добавит фото в таблицу, карточка покажет его без правок кода.
- **Технически — CSS 3D coverflow**, не библиотека: `perspective` на
  контейнере, каждая карточка — `position:absolute` в центре с
  `translateX/rotateY/translateZ/scale` по смещению от активного
  индекса (с зацикливанием по кругу). Перетаскивание — через
  `pointerdown` на контейнере, `pointermove`/`pointerup` вешаются на
  `window` (а не `setPointerCapture`+обработчики на самом контейнере —
  таким образом клик по карточке без драга долетает до `<Link>`
  и открывает каталог; `setPointerCapture` перенаправляет и
  последующий `click` на контейнер, из-за чего карточки переставали
  открываться — поймано и исправлено в процессе, см. тесты в этой же
  сессии). Порог движения 6px отличает клик от драга; после отпускания
  палец/мышь округляется до ближайшей карточки и доезжает CSS-переходом.
- **«Парящие» карточки, а не слайдер в рамке**: контейнер и карточки
  специально без `overflow-hidden` — карточки могут визуально выходить
  за пределы своей колонки (`lg:w-2/5`). Чтобы это не создавало
  реальный горизontal-скролл страницы (жёсткое правило сайта — 0
  hscroll на всех брейкпоинтах), на секцию хиро добавлен
  `overflow-x-clip` — обрезает ровно по границе самой секции,
  а не рамкой вокруг самой карусели, поэтому эффект «карточки парят
  над текстом» сохраняется, просто не вылезает за пределы окна.
  Проверено Playwright на 375/768/1024/1280/1440/1920 — hscroll нет
  нигде до и после.
- Стрелки prev/next под каруселью и `ArrowLeft`/`ArrowRight` на
  фокусе — доступность для тех, кто не может/не хочет тащить мышью;
  колесо мыши сознательно не перехватывается (в референсе крутило
  вертикальный скролл, но на обычной странице, а не в полноэкранном
  оверлее, это увело бы фокус от прокрутки страницы — решили не
  повторять этот кусок референса).

## SEO-инфраструктура: фавикон, OG-картинка, title-шаблон, соцсети

Владелец попросил «прописать заголовки и компоненты, чтобы SEO
подтягивалось органически и соцсети правильно читали ru/en». До этого
на сайте были canonical/hreflang/JSON-LD (заложены на этапе 10), но не
было favicon/OG-картинки вообще (карточка при шаринге в Telegram/VK/
WhatsApp была бы пустой), не было общего title-шаблона и 7 страниц не
имели description (важен и для сниппета в поиске, и как фолбэк для
og:description/twitter:description).

- **Фавикон и apple-touch-icon** — `src/app/icon.tsx` (32×32) и
  `src/app/apple-icon.tsx` (180×180), файловая конвенция Next
  (`next/og` `ImageResponse`), не привязаны к `[locale]` — иконка не
  зависит от языка. Логотипа-файла нет (см. `Logo`, читает
  `public/logo.svg` и иначе показывает текст) — тот же принцип здесь:
  буква «A» на фирменном тёмно-сером фоне (`#262626`), заменится сама,
  если/когда появится `logo.svg` и на основе него будет пересобран
  favicon.
- **OG/Twitter-картинка** — `src/app/[locale]/opengraph-image.tsx`
  (1200×630, тоже `ImageResponse`), лежит внутри `[locale]`, поэтому
  генерируется отдельно на ru/en с локализованным текстом. Вордмарк
  «AURA ROBOTICS» + жёлтая плашка-акцент + тэглайн на языке страницы.
- **`src/app/manifest.ts`** — веб-манифест (PWA-минимум): имя, цвета,
  ссылки на `/icon` и `/apple-icon`.
- **`generateMetadata` в `src/app/[locale]/layout.tsx`** (раньше был
  статичный `export const metadata`, локаль не учитывал):
  - `title: { default, template: "%s — Aura Robotics" }` — дочерние
    страницы, где `title` — простая строка, получают суффикс бесплатно,
    без правки каждой страницы;
  - `openGraph`/`twitter` — сайт, тип, og:locale + og:locale:alternate
    (соцсети должны понимать, какой язык у карточки); `og:title`/
    `og:description` НЕ переопределяются на уровне layout — по Metadata
    API Next.js сам берёт их из `title`/`description` дочерней
    страницы, если та их не переопределяет отдельно, значит уже
    существующие 24 `generateMetadata` по всему сайту получили верный
    og:title/og:description без единой правки;
  - `robots`/`verification` — `verification.google`/`.yandex` берутся
    из `GOOGLE_SITE_VERIFICATION`/`YANDEX_VERIFICATION` (пусто — тег не
    рендерится; коды подставит владелец в переменные окружения, когда
    заведёт сайт в Search Console/Вебмастере — руками в коде ничего
    менять не придётся);
  - строки — новый namespace `seo` в `messages/{ru,en}.json`
    (`defaultTitle`, `titleTemplate`, `defaultDescription`).
  - добавлен `websiteJsonLd()` (`src/lib/seo.ts`) — сущность WebSite
    рядом с уже существующим `organizationJsonLd()`.
- **Два заголовка с брендом внутри строки** (`/`, `/tours`,
  `/tours/[id]`) уже заканчивались на «Aura Robotics»/«Aura Robotics
  Tour» — с новым шаблоном получили бы задвоение («...— Aura Robotics
  Tour — Aura Robotics»). Исправлено через `title: { absolute: "..." }`
  — так строка идёт в `<title>` как есть, шаблон не применяется.
- **Найден и исправлен `favicon` 404 из-за миддлвара**: matcher
  next-intl (`src/middleware.ts`) исключал пути с точкой в них
  (`.*\\..*`) — это ловит `manifest.webmanifest`/`sitemap.xml`/
  `robots.txt`, но НЕ `/icon` и `/apple-icon` (в самом пути точки нет,
  расширение добавляется файловой конвенцией Next отдельно). Без
  исключения next-intl переписывал путь на локаль и Next не находил
  роут `[locale]/icon` (такого не существует — иконка вне `[locale]`)
  → 404. Добавлены явные исключения `icon`/`apple-icon` в matcher.
  Поймано не по логам, а руками: `curl` на `/icon` после сборки отдавал
  404, хотя файл был в `.next/server/app/icon`.
- **OG-картинка ru и один лишний редирект**: Next выводит абсолютный
  URL og:image из физического пути сегмента — буквально
  `/ru/opengraph-image`, хотя у ru как локали по умолчанию (as-needed)
  в реальных адресах префикса нет, и `/ru/...` отдаёт 307 на
  `/opengraph-image`. Пробовал переопределить `openGraph.images`
  вручную тем же `localeUrl`, что и canonical, — не сработало: Next
  подставляет автодетект файловой конвенции поверх любого explicit
  `images` в том же сегменте, это подтверждено на практике (у итоговой
  картинки не было даже `alt`, который я передавал только через
  metadata). Убрал мёртвый код, оставил редирект как есть — проверено
  вручную (`curl -L`), редирект резолвится в один хоп в валидный PNG
  1200×630, а Facebook/Telegram/VK/WhatsApp следуют за редиректом при
  загрузке og:image, так что это не проблема на практике.
- **Заполнены description на 7 страницах, где его не было**:
  `/faq`, `/contacts`, `/policy`, `/quiz`,
  `/production/[industry]`, `/production/equipment/[equipment]`,
  `/production/[industry]/[equipment]` — на обоих языках.
- **Product JSON-LD на карточке завода `/production/factory/[id]`** —
  раньше был только на карточке `/catalog/[category]/factory/[id]`
  (там есть цена категории). У производственных заводов единой цены
  нет (несколько категорий оборудования), поэтому `productJsonLd()`
  вызван без `priceFrom`/`priceTo` — функция это уже поддерживала.
- **Попутно найден и исправлен ещё один экземпляр старого бага**
  «справочник в коде вместо категорий из таблицы» (тот же класс, что
  уже чинили в `sitemap.ts` и `getEquipmentOptions()`): в
  `src/lib/production.ts` — `getEquipmentOptionsForSubIndustry()` и
  `getIntersectionParams()` — брали `equipmentTypes` напрямую вместо
  `getEquipmentOptions()`, из-за чего категории оборудования, заведённые
  только в Google Sheets (например `centralkitchen`, `smartchef`),
  никогда не попадали в связанные чипы на странице субиндустрии и в
  страницы пересечений `/production/[industry]/[equipment]` — не 404,
  а просто отсутствовали как маршрут. Страница пересечения
  (`production/[industry]/[equipment]/page.tsx`) заодно переведена на
  `getEquipmentOption()` вместо `equipmentTypes.find()`. Эффект виден
  прямо в выводе `next build`: до фикса `/production/meat/[equipment]`
  генерировал 2 пути, после — 5 (`meat`, `rice`, `thermal`,
  `vegetables`, `washing`); карта сайта выросла со 156 URL (после
  фикса) — сравнение до/после не сохранено, но прирост подтверждён по
  журналу сборки.
- QA: `tsc --noEmit`, `npm run lint`, `npm run build` — чисто;
